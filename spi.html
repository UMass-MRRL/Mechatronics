SPI Bus Inspector

The same three devices as the I²C bench, now on SPI: a controller UNO R4 Minima, a second Minima, and an Adafruit LSM6DS3TR-C breakout with 5 V-safe logic. Each peripheral gets its own chip-select wire. Step one clock edge at a time and tap any wire, driver, register, or board.

Good for: seeing the order of events on the wires, who drives each line, and what the code is doing while bits move.

Not for: verifying real-board wiring, exact timing, rise/fall limits or library behavior. Voltage thresholds, driver impedances and line capacitances are illustrative; edges are first-order RC with no ringing/noise, byte gaps are shortened, and library/interrupt delays are omitted. Code panels are instructional examples, not tested production sketches.

Bench

Controller driving Minima driving CIPO IMU driving CIPO Overbar on CS means active-low: LOW = selected, HIGH = released. Faded wire = LOW. Dashed = high impedance; red = contention.

I²C and SPI side by side

    

      
I²CSPI

      
Wires for these 3 devicesSDA, SCL, GND: 3 no matter how many devicesSCK, COPI, CIPO, GND + one CS per peripheral: 6 here

      
Who is talking to whom7-bit address sent on the busWhich CS wire is LOW

      
Did it arrive?ACK/NACK every byteNo acknowledgement. A missing or unpowered device returns whatever the floating CIPO wire reads, often 0xFF or 0x00, and nothing flags it.

      
DirectionHalf duplex: one sender at a time on SDAFull duplex: every clock moves one bit each way

      
Driver typeOpen-drain + pull-up resistor. Rising edges are slow RC charges.Push-pull. Both edges are fast, so clocks of several MHz are easy.

      
Typical speed100 kHz or 400 kHz1–20 MHz, set by the slowest device

      
Worst wiring mistakeMissing pull-ups: bus hangsTwo CS LOW: CIPO drivers short each other

      
Arduino peripheral modeWire.begin(address) works out of the boxThe standard SPI library is controller-only; a peripheral needs register-level code

    

  


  

    
Try this

    
    
      
  1. Watch both shift registers during one byte. After 8 clocks, what has happened to the controller's byte and the peripheral's byte?
    2. 
      
  2. In the encoder read, the first byte the controller receives is 0xA5, not data. Why does the Minima need a byte of delay before it can answer a command?
    3. 
      
  3. The controller sends 0x00 bytes while reading. What would change if it sent 0xFF instead? What would the IMU think if it sent 0xAC again?
    4. 
      
  4. Switch between mode 0 and mode 3. Which edge samples data in each? What stays the same?
    5. 
      
  5. Run the fault case and pause on a bit where the two peripherals disagree. Compute the CIPO voltage and the current from the driver resistances.
    6. 
      
  6. Set 10 MHz and 300 pF. Does the RC model indicate sufficient clock-edge margin? Compare with the I²C open-drain rise time, and explain why push-pull often supports faster clocks. This RC model alone does not certify a particular sensor maximum clock rate.
