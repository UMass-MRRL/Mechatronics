UART / Serial Baud-Rate Inspector

Transmit the same byte at different baud rates. The wire bits do not change, but their duration changes. A receiver configured for the wrong baud rate samples at different points and can decode the wrong data.

Educational model only: Idealized 8N1 UART receiver samples, not an implementation of a particular UART peripheral or a hardware diagnostic. Real oversampling, resynchronization, clock error, noise and line-driver voltage levels are not modeled.

Physical TX waveform and receiver sample instants

Three back-to-back copies of the same 8N1 frame are sent for context. The receiver locks onto the first falling start edge, then samples the 8 data-bit centers and the stop-bit center using its own clock. This models one attempted frame decode, not a complete UART state machine.

Try this

  1. Start with matching 9,600 baud. All eight data samples land near the centers of the transmitted bits.
  2. Set the receiver to twice the baud rate. It samples faster, sometimes sampling the same transmitted bit multiple times. What binary value does it reconstruct?
  3. Set the receiver to half the baud rate. Its later samples extend into the next frame. Why can an incorrect byte sometimes still pass a stop-bit check?
  4. Try a 5% error. Notice how sample timing drift accumulates from bit 0 to bit 7. Does the particular data pattern affect when an error becomes visible?
  5. Change the transmitter from 9,600 to 115,200 baud while keeping the receiver/transmitter ratio unchanged. The absolute pulse widths shrink, but the decoding outcome does not change in this idealized model.

Assumptions: 8 data bits, no parity, 1 stop bit (8N1); both ends share a reference HIGH/LOW voltage and agree on polarity; an ideal noiseless signal; perfect start-edge detection; center-of-bit sampling with a fixed receiver period; no oversampling, jitter, buffering, synchronizers, or baud-rate estimation. Baud rate alone does not change the TX bit sequence, and a framing check is not a data-integrity check.
